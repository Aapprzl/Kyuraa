PERUBAHAN RIWAYAT (PALING PENTING)
================================================================

SEBELUM:
  - Sidebar KANAN berisi riwayat transaksi (hanya preview 50 char)
  - Klik = buka modal pop up terpisah
  - Tidak bisa melihat percakapan penuh secara natural

SESUDAH (mirip Claude.ai):
  - Sidebar KIRI berisi daftar SESI percakapan
  - Setiap sesi = satu percakapan lengkap (seperti chat thread)
  - Klik sesi = chat area menampilkan seluruh percakapan sesi itu
  - Sesi aktif highlighted di sidebar
  - Bisa scroll ke atas untuk lihat riwayat
  - Nama sesi = 50 karakter pertama pesan pertama (auto-generated)
  - Tombol hapus sesi (muncul saat hover)
  - Tombol "+ Sesi Baru" di atas sidebar

PENYIMPANAN SESI:
  - Backend: SQLite (sudah ada di session_store.py)
  - Setiap sesi punya: session_id, nama, tanggal, messages[]
  - Endpoint baru: GET /sessions/list
  - Endpoint baru: GET /sessions/{id}/messages
  - Endpoint baru: DELETE /sessions/{id}

TAHAP 3 — TAMBAH ENDPOINT SESI DI SERVER.PY
================================================================

Berikan prompt ini ke OpenCode:

"Tambahkan endpoint baru di src/gateway/server.py:

1. GET /sessions
   Return daftar semua sesi:
   { sessions: [{ id, name, created_at, updated_at,
                  message_count }] }
   Urutkan: terbaru di atas

2. GET /sessions/{session_id}/messages
   Return semua pesan dalam satu sesi:
   { session_id, name, messages: [{ role, content,
                                    timestamp }] }

3. DELETE /sessions/{session_id}
   Hapus satu sesi dan semua pesannya
   Return: { success: true }

4. PATCH /sessions/{session_id}/name
   Body: { name: 'nama baru' }
   Update nama sesi
   Return: { success: true }

Pastikan semua endpoint menggunakan logger dari utils/logger.py.
Tampilkan bagian yang ditambahkan setelah selesai."

TAHAP 5 — MIGRASI JAVASCRIPT (WEBSOCKET + SESI)
================================================================

Berikan prompt ini ke OpenCode:

"Tambahkan JavaScript ke index.html baru. Ini logika utama:

1. WEBSOCKET CONNECTION:
   Sambungkan ke ws://127.0.0.1:8766/ws/{session_id}
   Gunakan session_id dari sesi yang sedang aktif di sidebar

2. LOAD DAFTAR SESI:
   Saat halaman load: fetch GET /sessions
   Render ke #sessions-list sebagai list item
   Setiap item tampilkan: nama sesi + tanggal relative
   (hari ini, kemarin, 2 hari lalu, dll)
   Item yang sedang aktif: highlighted dengan accent color
   Hover: tampilkan tombol hapus (🗑) di kanan

3. KLIK SESI:
   Fetch GET /sessions/{id}/messages
   Render semua pesan ke #messages-container
   Sambungkan WebSocket ke sesi tersebut
   Scroll ke pesan terbawah

4. TOMBOL + SESI BARU:
   Generate session_id baru (uuid)
   Tambahkan ke daftar sesi di sidebar
   Kosongkan #messages-container
   Sambungkan WebSocket ke sesi baru
   Focus ke input

5. KIRIM PESAN:
   Ambil teks dari textarea
   Tambah bubble user ke #messages-container
   Kirim via WebSocket: { type: 'message', content: teks }
   Scroll ke bawah
   Kosongkan textarea

6. TERIMA RESPONSE (STREAMING):
   type 'token': append ke bubble agent yang sedang aktif
   type 'done': finalize bubble, update nama sesi di sidebar
   type 'error': tampilkan error message

7. HAPUS SESI:
   Klik tombol hapus di item sidebar
   Tampilkan konfirmasi custom modal (bukan browser confirm)
   Jika OK: DELETE /sessions/{id}
   Hapus item dari sidebar
   Jika sesi yang dihapus adalah aktif: buat sesi baru

8. SETTINGS PANEL:
   Klik ⚙ di header atau sidebar footer:
   Toggle #settings-overlay visible/hidden
   Pindahkan semua logika setting yang sudah ada
   (model, API key, manajemen skill) ke dalam panel ini

Tampilkan bagian JavaScript yang paling penting setelah selesai."
